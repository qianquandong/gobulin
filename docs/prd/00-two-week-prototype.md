# 0. 两周原型：范围、试玩与决策

> v0.2 · **[决定] 当前开发入口**。M0 是 10 个工作日的可玩原型，不是完整 P0 的前两周施工。只有通过本章闸门，才批准 M1。所有人数阈值均为内部决策假设，不是行业基准，也不是统计显著性结论。

## 0.1 唯一目标

验证玩家能否在第一次游玩中形成“观察敌人 → 自己改锻 → 看到战斗变化 → 愿意再试”的循环。首个可见的形态改变目标为可交互后 60 秒内（冷启动单列）；理解效果和自主决策必须分开测量。

## 0.2 必做与不做

| 范围 | 两周交付要求 |
|---|---|
| 设备与输入 | 一台团队现有 iPhone 真机，竖屏单手；程序第 1 天按已有经验定引擎。不做多机型适配 |
| 锻造 | Blade / Hilt / Rune、3 形态、Ember；预算固定、即时预览、Undo / Reset / Deliver；Temper 固定 3，隐藏节奏玩法；提供 Cancel，无消耗退出当前锻造 |
| 战斗 | 英雄固定、3 类普通敌人、20 Hz 逻辑；形状轮廓、命中计数、护甲灰字、护盾点、灼烧反馈；每场开始满血 |
| 操作闭环 | 3 格武器架、单击换装、Retry、原因说明；引导可开推荐，迁移题必须关掉推荐与配方 |
| 内容 | 1 段首分钟演示、3 个单特性学习场景、2 个未展示过的混合迁移场景；允许复用敌人，不能把学习题原样换皮当迁移题 |
| 美术音效 | 简单色块/占位角色；刀身形变、3 种攻击轮廓、敲击音效和触感必须可辨。无需最终角色动画 |
| 数据与交付 | 本地事件 JSONL、单场重置、配置版本/种子、录像记录表；可安装包、配置、测试结果与逐人决策表 |
| 明确不做 | Boss、正式 1–20 关流程、Coins/Ore/Stones/Gems、设施升级、Cart/离线、节奏小游戏、Quick Forge、Codex、商店/IAP/广告、云存档、远程配置、A/B 平台、推送、最终美术 |

原型不需要持久化进度，但需持续写出测试日志；重启从当前测试块重新开始并标记技术中断。正式版的存档、经济和 AC-01–37 不是 M0 交付要求。

## 0.3 固定配置与内容准备

- `build_mode=prototype`，所有锻造、换装、重试无资源消耗，无时间等待，不发放成长奖励；独立测试存档，不能导入正式进度。
- 首分钟演示：MD=10、预算=7、HP=100、Temper=3、无符文；初始提供 Needle B2/H2。刷一组 Mushling，提示可敲 Blade，玩家交付 Broad 后应能看到一击命中至少 3 个。允许重复演示，不伪造伤害或命中。
- 学习与迁移：MD=20、预算=10、HP=164、Temper=3；Ember 从学习阶段开始可用。敌人用第 8 关的基础成长属性，不含 Boss。三个学习场景分别展示 Swarm、Armor、Guard；每场 1 波，目标 20–45 秒。
- 两道迁移题分别为 **Swarm + Armor** 与 **Guard + Swarm**，各 1–2 波；从 4 Mushling + 1 Shellback、2 Sprite + 3 Mushling 的初稿开始调。第 6 天前锁定数量、方向、波次、种子和版本，此后同批受试者配置相同。每道迁移题都以相同的预置 Needle B3/H6、空余 2 格开始，避免上一题装备造成顺序优势。
- 迁移题上线试玩前，策划必须为每题登记至少 **2 个行为不同的有效答案**（形态不同，或形态相同但通过 Ember 改变对甲方式；不能只是同一配方多一点伤害）。各答案在固定种子 1–10 中至少 8 次胜利；起始不匹配武器至多 2 次胜利。未达到时调关卡，不给玩家唯一强制配方。数值证据须附配置和结果，当前仓库尚未验证这些新场景。
- 原型只实现当前范围所需公式；E1–E5 的武器公式与模拟器一致。Frost / Spark、正式关卡完整回归在后续里程碑验收。

## 0.4 首分钟与十五分钟测试流程

| 时间 | 内容 | 主持人与提示规则 |
|---|---|---|
| 0:00–0:10 | 直接看到 Needle 对群怪的表现，可立即敲击 | 无标题等待、无剧情停留、无工坊菜单 |
| 0:10–1:00 | 首次锻成 Broad、交付、看到横扫至少 3 个敌人 | 只教第一次敲击与 Deliver；可提示 Blade；记录首次形态改变和第一次多目标命中时间 |
| 1:00–5:00 | 三个单特性学习场景，自己试分配 | 可显示主因与方向，不锁定敲击区域；不教具体 B/H/R 配方；失败可重试 |
| 5:00–11:00 | 两道迁移题，各最多 3 分钟/3 次尝试，题序交替分配 | 关闭 Good/Weak vs、推荐框、区域呼吸、方向建议、3 次失败配方及教学对白；保留真实敌人特性、数值与失败主因。不给问卷答案，也不要求有声思维 |
| 11:00–12:00 | 事后解释与问卷 | 先问“你为什么这样改”，再给选项；追问用 `prototype_reason`；不能在迁移题前用问卷提醒答案 |
| 12:00–15:00 | 可选择结束或自由继续最多 3 分钟 | 只说一次中性邀请 `prototype_continue`；报酬与是否继续无关；不增加奖励、不催促完成图鉴 |

不要求十五分钟走完正式第 1–8 关。学习阶段没有在第 5 分钟前完成者仍记录为未达标，主持人可直接载入迁移配置收集诊断数据，但该补充结果不计入主指标成功数。

## 0.5 招募、记录与指标

第 1 周预约 **12 名**没有读过 PRD、没有参加内部试玩的目标用户；实际外测第 9–10 天完成。内部 3 人排查操作与崩溃不计入样本。有效样本不足 12 时只出诊断，不判定通过；追加测试时间单列。不得因为用户玩得差或提前退出而替换样本；只有无法运行的设备故障可剔除，须保留故障日志和替补记录。

| 指标 | 操作定义 | M0 通过门槛 [假设] |
|---|---|---|
| 首分钟反馈 | 从可交互画面出现起到亲手交付新形态并命中 ≥3 目标；另记录冷启动耗时 | ≥9/12 人在 60 秒内完成；不能用自动交付代替 |
| 行为理解 | 迁移后、不看选项，用自己的话说明“更宽会打更多敌人，代价是更慢” | ≥9/12 人同时说出效果和取舍 |
| 无提示迁移 | 每人 2 题；题内首次自由改锻/换装后，能在剩余尝试内通关，并在事后说明与敌人机制相关的理由；没有提示、没有提高预算/MD/HP | ≥8/12 人至少通过 1 题，且两题合计 ≥14/24 次成功。即使初始武器侥幸赢也不算迁移成功 |
| 继续尝试 | 核心任务完成后，自愿继续且实际完成至少 1 次新的分配并观察其战斗 | ≥7/12 人；只口头说“喜欢”不算 |
| 测试有效性 | 无奖励/等待，配置固定，日志能关联敲击→交付→战斗，所有提示都有记录 | 无影响判断的崩溃、资源阻塞或提示泄漏；技术失败单列 |

按人和按题同时报告分子/分母；退出、超时、直接重复原配方均留在分母。每人一行记录：配置、题序、首次反馈秒数、两题原/新 B/H/R、尝试数、是否得到提示、是否成功、理由原话、是否继续。任何主持人泄露答案使该题主指标记为未独立完成，补测只用于诊断。

M0 最小事件：`prototype_start`、`forge_complete`、`weapon_swap`、`stage_end`、`hint_shown`、`transfer_result`、`free_play_choice`、`prototype_end`。每条含 participant_id、build_mode、config_version、case_id、seed、elapsed_ms；装备事件另含 B/H/R、form、rune；结果含 attempts、success、hint_exposed、exit_reason。原型只导出本地文件，不接商业分析 SDK。

## 0.6 十个工作日与决策

| 工作日 | 程序 | 策划/美术 | 当天验收 |
|---|---|---|---|
| 1–2 | 真机运行、三区域输入、确定性武器公式、基本战斗 | 预约用户；确认占位表现、初稿场景 | 敲击到形态变化可操作，公式对齐 |
| 3–4 | 3 形态、3 类敌人、Ember、交付/换装/Retry | 打磨首分钟变化与敲击反馈 | 能用两种方式解决同一特性 |
| 5–6 | 预览、日志、提示开关、场景重置 | 校准并锁定两题、完成 10 种子多答案验证 | 首分钟可玩，迁移题预检通过 |
| 7–8 | 真机修错、日志核对、打包 | 内部排障 3 人，排除误触和看不懂的反馈 | 外测配置冻结；未完成则停止加功能 |
| 9–10 | 支持安装与故障定位 | 12 人测试、逐人整理、录屏复盘 | 提交包、配置、多答案证据、原始记录、结论 |

- **继续 M1**：全部门槛达到，附真实结果。通过仅支持进一步开发，不代表已证明留存或商业可行。
- **调整**：测试有效但任一门槛未达；明确一个主要原因，最多追加 5 个工作日修改，用新的 12 人复测同口径。不用追加金币、更多关卡或强配方提示掩盖迁移失败。
- **停止/转向**：完成一次调整后仍未达到上述门槛；或明显只有照提示点选、没有主动尝试。记录否定了哪个假设，再决定是否保留锻造表现转向其他战斗玩法。
- **测试无效**：样本不足、答案泄漏普遍、关键日志缺失或版本中途改变；先补测试，不据此声称玩法通过/失败。两周结束必须披露完成度，不能默认为通过。

M0 不测 D1/D7、付费和离线经济。后续版本的验证条件见 [11.6](11-data-validation.md#116-继续调整停止的条件)；M0 后计划见 [12.3](12-scope-schedule-acceptance.md#123-里程碑依赖与工作量)。
