# TestFlight 到 App Store 上线手册

适用《Goblin Forge》iPhone 首测版。**这是未来执行清单；目前没有已上传 build 或已完成的 Apple 配置。** Claude 准备工程、构建与技术证据；Codex 准备商店视觉/文案并评审；负责人提供账号、业务资料、发布地区和最终发布决定。

Apple 官方资料核对日期：**2026-10-11**。以下“项目要求”是本项目的放行标准；“Apple 要求”附官方链接。实际提交前 Claude 再次核对当日要求及 Connect 必填项，记录到发布报告，不以本页替代实时平台状态。

## R0：开工时就准备的条件

| 项目 | 责任人 | 做法与完成证据 |
|---|---|---|
| Mac / 构建环境 | 负责人提供，Claude 检查 | 可运行所选引擎与 Xcode 的 Mac 或受控 macOS 构建机；记录系统/引擎/Xcode/SDK；Windows 可做文档和部分代码，但不能据此宣称 iOS 归档完成 |
| iPhone | 负责人 | M0 一台，发布前按 QA 扩展矩阵；记录设备/OS，证明能安装并运行 |
| Developer Program 与权限 | 负责人 | 检查会员状态，指定 Account Holder 与有权限的提交人员；成员各用自己的账号，开发/发布凭据由安全存储管理 |
| App 身份 | 负责人 + Claude | 确定最终名称、Bundle ID、SKU、主语言英文、iPhone 设备范围；Bundle ID 与签名/商品归属一致，记录到工程说明 |
| Signing 与能力 | Claude | 开发/分发签名配置、entitlements、所需 capabilities；M0 只启用必需项，iCloud 在对应阶段接入；证书/密钥不入 Git |
| 招募和安装途径 | 负责人 | M0 优先线下同机试玩；需远程安装则提前处理分发和审核，不将外测账号当内部开发成员随意添加 |
| 名称/素材/音乐权利 | 负责人，Codex 提供材料 | M3 前核查工作名与拟用资产；保存核查结果。工作名不等于已完成商标检索 |

账号和环境未知时写 `待确认`；实际无法访问再写 `BLOCKED`。可独立完成的规则代码继续推进，真机/分发关口保持未通过。

## R1：构建版本与可追溯性

每个候选包记录：Git SHA、工程/依赖锁定版本、资源版本、config_version、App 版本、唯一递增 build 号、构建机器/工具链、构建命令、签名方式、归档与符号文件位置。保留 `.xcarchive`、对应符号文件、构建日志和发布配置；产物和签名资料放受控存储，公开仓库保留不含凭据的索引。

**Apple 工具链要求**：当前已生效的上传底线为 Xcode 26 或更新版本、iOS 26 SDK 或更新版本；官方还已公告 2027 年 4 月起的新 SDK 要求。实际发布日重新核对，选择引擎可支持的有效工具链。项目暂定最低运行系统 iOS 16，与上传 SDK 的版本不同，不要误设成必须 iOS 26 才能玩。[当前要求](https://developer.apple.com/news/upcoming-requirements/)、[提交公告](https://developer.apple.com/app-store/submitting/)。

Claude 在选定引擎后提供一条完整路径：检出 → 依赖恢复 → 配置 → 测试 → Release 构建 → Archive/Validate → 上传。Unity 路径要包括生成 Xcode 工程与插件桥接；SpriteKit 路径要包括 scheme/target 和 Swift 测试。所有脚本使用 secret 引用，不把凭据写入命令示例。至少让另一人/干净构建环境按说明复现一次。

## R2：TestFlight

1. Claude 先完成新装/升级冒烟和内部真机回归，上传正确 build，等待处理完成，填写测试说明及出口合规问项。
2. 负责人配置合适的内部测试者，测试安装、启动、日志、崩溃符号、关键流程。先修关键故障再扩大人数。
3. 外部测试填写 Beta 描述、反馈联系渠道和审核所需说明；将选定 build 加入外部组并提交 Beta 审核。**首个外部 build 需要完整审核，后续同版本 build 仍可能被审核**。只有获准的 build 才对外分发。[Apple 外部测试流程](https://developer.apple.com/help/app-store-connect/test-a-beta-version/invite-external-testers)。
4. M0 使用独立 prototype 配置并按第 0 章测试；M3 使用正式 economy 配置、真实新安装和固定分组。TestFlight 测试说明与主持词不能泄漏迁移题答案。
5. 负责人安排招募；Claude 提供安装和故障处理；Codex 复核记录。版本、配置、观测窗口固定，版本切换建立新 cohort 或明确分层。
6. 导出测试反馈/崩溃/行为记录，完成阶段报告。Beta 审核通过不等于 App Store 审核通过，安装成功也不等于玩法闸门通过。

## R3：SDK、隐私与权限

M0 不接商业 SDK。M3/M5 每加入一个 SDK，Claude 更新下表的逐 SDK 实际记录，不能写“匿名所以不用申报”。

| 要记录 | 验证方式 |
|---|---|
| SDK 名称/版本、用途、接收方、数据字段 | 对照实际配置、SDK 官方文档及运行时数据流 |
| 是否离开设备、与用户关联、用于追踪、保留/删除方式 | 记录实际用途与接收方行为；随机 install_id 不自动代表匿名 |
| 启动时点与允许/拒绝/受限状态 | 真机抓取/日志核对，确认未授权时追踪功能不启用 |
| 隐私清单、required reason API 与适用 SDK 签名 | 核对 app 和全部依赖，生成/审查 Xcode 隐私报告；只声明实际使用的理由 |

**Apple 要求**：申报涵盖应用和第三方 SDK 的实际数据实践，提供公开可访问的隐私政策 URL；不能仅根据自己写的代码填“未收集数据”。[App Privacy Details](https://developer.apple.com/app-store/app-privacy-details/)。

**ATT 处理**：先明确是否追踪/访问广告标识符；需要时先获得 ATT 授权，再启用对应行为。拒绝、受限或未决定时不得用其他标识替代追踪。项目仅在确有需求且状态可请求时，于第 2 次会话或更晚给清楚说明；没有追踪的版本不因日程自动弹窗。拒绝不影响核心玩法和奖励。[Apple 隐私与追踪说明](https://developer.apple.com/app-store/user-privacy-and-data-use/)。

Codex 根据数据清单起草玩家隐私说明；负责人确认运营主体、联系方式、保留/删除做法与托管地址；Claude 接入真实页面和设置入口。隐私标签、清单和实际行为三者分别核对。通知权限只在玩家选择提醒时申请；不用本作不需要的权限。

## R4：IAP 与广告

- 负责人完成适用的付费协议、银行税务和地区/价格决定；Claude 建立商品 ID 与客户端配置的一一映射。PRD 的人民币参考价不能硬编码为全球展示价格，展示 StoreKit 返回的本地化价格。
- 每个上线商品准备类型、名称、描述、价格/可用地区和审核截图；首批消耗型/非消耗型商品与新 App 版本放在同一次提交中，逐项核对状态。[Apple IAP 提交流程](https://developer.apple.com/help/app-store-connect/manage-submissions-to-app-review/submit-an-in-app-purchase)。
- 先本地 StoreKit 测试，再 Sandbox/TestFlight 真机：成功、取消、待批准、断网、验签失败、重复交易、杀进程补发、恢复和退款。只用测试环境产生测试交易，不能把本地模拟结果当真实平台回归。
- 免广告权益与消耗材料分账；Restore Purchases 入口可找，消耗品恢复边界遵守 PRD。商品永久权益和 Starter Kit 消耗内容的重装策略须在测试记录里逐项验证。
- 广告开发/测试使用 SDK 测试模式；上线前核对正式 placement 和额度配置。失败不扣次数、重复回调不重复发奖、首通 7 前不出现商业入口，拒绝 ATT 不影响奖励。
- 完成 M5 全来源经济模拟与分组结果再放行价格/额度。上架后实际付费、收益和恢复的烟测由负责人安排，涉及真实购买先明确具体测试交易，不让脚本盲买。

## R5：商店页与审核资料

| 材料 | 主责 | 放行检查 |
|---|---|---|
| 英文名称、副标题、描述、关键词、类别 | Codex 起草；负责人确认 | 与实际功能一致；名称权利核查完成；限制按当前 Connect；strings.md 登记玩家可见文案 |
| 图标、6 张截图、可选预览 | Codex；Claude 提供真实画面 | 取自候选 build；不展示未上线功能；截图尺寸按实际支持设备与当前规范导出；见 [Apple 素材管理](https://developer.apple.com/help/app-store-connect/manage-app-information/manage-your-app-store-assets) |
| Support URL、Privacy Policy URL | 负责人托管/确认，Claude 接入 | 公网可访问；支持联系方式有效；页面和应用主体一致，不能用占位地址 |
| 年龄评级、内容权利、出口合规 | 负责人据实填写，Claude 提供技术清单 | 根据最终游戏、广告、SDK 和加密使用答题，不预填固定年龄或“一律豁免” |
| 隐私与可访问性声明 | Claude 提供实际测试，负责人确认 | 只声明已核验的支持；不因有按钮就宣称完整 VoiceOver 支持 |
| 价格、地区、平台可用性 | 负责人 | 首测市场沿用 PRD 假设另行确认；不默认全球发布；核查 iPhone 应用在 Mac/Vision Pro 等渠道的可用性，只承诺实际覆盖的平台 |
| App Review 联系信息与说明 | 负责人 + Claude | 解释玩法、无账号模式、离线功能、商品/广告位置、恢复路径；无账户系统则不虚构测试登录 |

Apple 要求提交内容准确反映应用；截图/预览和付费功能说明按 [审核规则 2.3](https://developer.apple.com/app-store/review/guidelines/#accurate-metadata) 核对。年龄评级和隐私问项按提交时的最新表填写。扩大到新地区前，负责人核对该地区 Connect 的额外资料及发行要求，不因英语已支持就默认可全球发行。

审核说明应给可执行的普通玩家路径，例如“完成第 7 关后从工坊进入商店，设置可恢复购买”，并附实测耗时。若关键功能需要等待，提供准确解释或审核支持材料；不能偷偷给审核员另一套行为。移除调试入口、测试广告、作弊按钮与未声明功能；所有提供给审核的资源持续可用。

## R6：发布候选版验收

Claude 为同一个 RC 提交以下证据包，Codex 完成产品/美术复核，负责人决定放行：

- [ ] App version/build/Git SHA/config/资源版本锁定，归档与符号文件可取回。
- [ ] QA 适用 AC、功能/性能/购买/广告/云存档矩阵完成；S0/S1 为零，S2 有接受记录；所有未测项可见。
- [ ] 免费自然路径跑通 1–20，教程保护、无提示实验隔离、经济来源账正确。
- [ ] 最低支持设备和当前正式 OS 已测；英文无截断，触摸区域、安全区、静音/减少特效正常。
- [ ] 隐私/SDK 清单和实际数据流一致，URL、年龄/出口等声明及商品材料完整。
- [ ] 商店素材为实际 RC 画面，无占位图、假截图或未开放功能。
- [ ] 崩溃可符号化、支持联系方式可用、严重问题处理人和热修复流程明确。
- [ ] 负责人确认具体 build、配置、发布地区、商品价格和发布时间。

只要缺适用的关键证据，状态保持 NOT READY；不能把复选框模板直接批量勾选。材料全部可审阅后再做具体版本的发布决定。

## R7：提交审核与处理驳回

1. Claude 上传并验证 build，完成 Connect 元数据与同批 IAP；负责人/有权限的执行人复核选中的版本与构建号。
2. 项目选择**手动发布**，避免审核通过即在未完成业务准备时自动上线。[Apple 发布选项](https://developer.apple.com/help/app-store-connect/manage-your-apps-availability/select-an-app-store-version-release-option)。
3. 将 App 版本及商品添加到审核提交，再执行真正的 Submit for Review。仅 Add for Review 不代表已经送审。[Apple 提交步骤](https://developer.apple.com/help/app-store-connect/manage-submissions-to-app-review/submit-an-app)。保存提交时间、版本及状态。
4. 若被拒，负责人/Claude 读取具体理由并建对应问题；Codex 修文案/视觉/规则，Claude 修实现/配置；附复现、解释或修复证据，必要时新 build 再提交。不能承诺 Apple 必然在某天批准。
5. 审核通过后保留待手动发布状态，最终复核线上配置/商品/支持入口和目标市场，记录负责人对具体版本的放行。

## R8：首次上线与随后一周

首次上架采用已确认地区的手动发布。Apple 的 phased release 是**版本更新的自动更新分批机制**，不要把首版上线计划写成这个功能；后续更新可评估使用。[Apple 分批更新说明](https://developer.apple.com/help/app-store-connect/update-your-app/release-a-version-update-in-phases)。

| 时间 | 执行人 | 要做的实际检查 |
|---|---|---|
| 发布时 | 负责人 | 在 Connect 发布指定版本；记录版本、地区、时间；确认商店可下载后再开始宣传/投放 |
| 可下载后 | Claude + 测试员 | 用商店下载包新装，跑首分钟、教程、存档/重启、链接、真实商品展示；对既有权益做恢复冒烟；检查线上事件版本 |
| 首日 | Claude 技术、Codex 产品、负责人运营 | 检查启动/崩溃、支付失败/重复发奖、卡关和客服；报告人数与版本，低样本不宣称指标稳定 |
| 首周每天 | 同上 | 成熟 cohort 的 D1、教程完成、理解/迁移、资源阻塞与内容耗尽；分广告/宝石/Supply 看经济；检查 D7 内容充分性 |
| 观察窗成熟后 | Codex 汇总，负责人决定 | 按 PRD 11.6 决策；未达标按限次迭代；达到可解释的体验/留存/经济目标才讨论扩大地区与预算 |

以上是负责人安排的工作节奏，不代表已创建自动监控任务或已有人值守。

## R9：事故和热修复

发现启动失败、丢档、重复扣费/发货等 S0：Claude 定位版本并保留证据，负责人暂停扩量/投放，必要时处理可用性；若已部署且验证过的开关可以安全止损，关闭对应广告/商品等入口。已有离线玩家可能仍使用旧配置，不能承诺远程开关会立即覆盖所有设备。

客户端二进制不能被远程配置“降回旧版”。修复时用新的 build/版本，回归失败路径、存档迁移及核心闭环，重新提审/发布；后续更新采用分批发布时可以暂停继续扩散，但已更新玩家仍需修复包。保留原始存档/交易证据，补偿方案由负责人确认，不靠再次发放全部购买掩盖账目。

关闭事故前提交：影响范围、时间线、根因、修复 PR/构建、回归、用户处理和避免复发措施。每个版本同步更新支持说明与下一批发布清单。
