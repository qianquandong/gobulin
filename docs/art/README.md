# 美术方向与制作交接

主责：Codex。Claude 负责资源接口、导入、程序动画/粒子和性能；负责人确认关键视觉方向与素材权利。**本文件是制作规范，当前尚未交付最终图片、骨骼或音频。** 完成状态看 [素材清单](asset-manifest.md)。

## 视觉目标

方向定为“苔藓森林里的铜火工坊”：温暖、滑稽、手工感的 2D 风格化形体。上方森林用较冷、低饱和色，锻造台用暖色；最高对比留给武器、敌人特性和可操作区域。先让玩家看懂“形状变了，打法就变了”，再丰富装饰。

不是像素画；采用清晰外轮廓、少量大色面、有限材质纹理。角色小比例下不依赖细碎花纹。初稿色板是项目设计值，最终以真机可读性调整：

| 用途 | 基准色 | 约束 |
|---|---|---|
| 深色轮廓 / 工坊暗部 | `#252A28` | 避免全黑大块吞掉轮廓 |
| 森林主色 / 苔藓 | `#466854` / `#809461` | 背景对比低于敌人与武器 |
| 铜件 / 木面 | `#B87942` / `#654836` | 热光只用于实际敲击、炉火及 Ember |
| 钢铁高光 / 正文 | `#D9E2DB` / `#F3E8D1` | 武器轮廓须在森林和工坊两种背景都清楚 |
| 元素反馈 | Ember 橙、Frost 青、Spark 黄 | 与 PRD 8.3 的数字颜色语言一致；配图形/动作区分，不能只靠颜色 |

## 角色、敌人和武器设计

| 对象 | 形体要求 | 战斗或交互读法 |
|---|---|---|
| Pip | 短身、清楚的手与武器挂点、面部细节从简 | 武器独立于身体；三套攻击一眼能分出刺/扫/旋 |
| Gristle | 大耳朵哥布林、围裙、粗手锤与铜件；表情用眉眼和肩膀变化 | 敲击方向对准三分区；不让脸/锤遮住点数、预览或 Deliver |
| Mushling / Swarm | 圆蘑菇顶、小腿、群体密度明显 | 单体轮廓简单，成群时仍可数出多目标命中 |
| Shellback / Armor | 低矮横向甲壳、清楚的大甲片 | 灰色减伤数字加甲壳“铛”反馈；不能画成可打碎但实际上不会破的甲 |
| Bramble Sprite / Guard | 竖向枝叶轮廓、独立可计数护盾点 | 护盾受击/恢复和 HP 受击用不同反馈；不能只换一种绿色 |
| Needle | 细长刀身，小横截面 | 单向刺击，命中范围窄 |
| Broad | 宽扁刀身，明显横向重量 | 150° 扫击；覆盖更宽、节奏变慢 |
| Great | 厚重长刃，重量和回收动作更明显 | 360° 旋斩；不能因视觉夸张扩大真实命中半径 |

Boss 基于 PRD 10.1 的 Queen Mushla / Ironhide / Thornwarden 与 Ironthorn Warden 复用方案。先通过三种普通敌人与武器的可读性验收，再批量生产 Boss；不在 M0 做 Boss 定稿。

## 画面、UI 与反馈

- 布局沿用 PRD 8：390×844 pt 基准，上方约 45%、下方约 55%，支持安全区。按钮至少 44×44 pt；敲击区至少 64×64 pt，区间留 8 pt 死区。
- UI 使用独立按钮底、状态层、图标和实时文字，不把英文或资源数量烘焙进背景图。正文、数字大小沿用 PRD，真实最小设备检查截断。
- 三形态轮廓由 Claude 按真实配置绘制。Codex 提供线宽、明暗和衰减参考，不交付与命中逻辑脱节的预烘焙扇形。
- 敲击顺序为触点反馈 → 坯料形变 → 预览改变 → 交付轨迹 → 下一次攻击可见改变。敲击声音和震动服务于时点，不能用长动画阻塞后续输入。
- 单击命中轮廓强化、数字与命中计数同时可见；Reduce Effects 去掉装饰粒子和震屏后，仍保留所有判读战斗所需信息。
- 迁移题的美术状态也属于实验控制：区域呼吸、推荐描边、配方气泡、方向箭头都必须可统一关闭。

## 资产接口

这些是工程无关的初始接口；BOOT-01 后由 Claude 填写引擎单位、压缩/过滤和 atlas 导入设置。若需改变尺寸或锚点，先更新清单再重新导出。

| 类型 | 源文件/导出约定 | 基准与锚点 |
|---|---|---|
| 角色/敌人 | 分层可编辑源文件；导出 sRGB 透明 PNG；身体与武器/特性标志分层 | 普通角色原始画布 512×512 px；脚底中心 pivot=(0.5,0.12)，坐标原点左下；引擎按约定换算 |
| 武器 | 透明 PNG，刀身/柄/符文层独立；不预带角色影子 | 原始画布 512×512 px；握柄锚点首稿=(0.5,0.18)；同族同画布，禁止逐帧自动裁切改变锚点 |
| 场景 | 可编辑分层；远/中/近景独立导出；可交互物单独 | 390×844 pt 布局参考，生产底图可用 1170×2532 px；实际上下区域按安全区裁切验证，不硬拉伸 |
| UI | 图标透明 PNG；面板/按钮带九宫格切片边距；文本运行时排版 | 常用图标母版 256×256 px；32/48 pt 显示时检查；逻辑点击区域独立于图片 |
| 动画 | M0 用静态层+程序变换；M1 起按选定引擎使用骨骼/分件，必要时序列帧 | 武器挂点与角色分层稳定；说明朝向、循环、起手/命中/收招归一化时点；逻辑事件驱动动画 |
| 特效 | 透明纹理+参数说明，或程序图形规范 | 每个效果写清持续时长、叠层、是否随朝向、Reduce Effects 替代；禁止烧进背景 |
| 音效/音乐 | 可授权的无损源文件及实际引擎压缩产物 | 明确循环点、响度匹配、静音/音量控制；听感与授权分别验收 |

以上是导出母版尺寸，不是要求全部原尺寸常驻内存。Claude 按实际显示尺寸缩放并打 atlas，测峰值内存和包体；资源不能因“AI 生成了大图”无限增大。A0 临时色块也用同一 ID/尺寸接口。

建议实际制作后使用以下目录（当前仅规划，不代表目录已有资源）：

```text
assets/source/<asset_id>/          可编辑源文件或受控源文件索引
assets/export/<asset_id>/v001/     引擎可导入文件与 metadata.json
assets/licenses/                   授权与生成来源摘要
docs/art/reviews/<batch-id>.md     实际导入评审与问题
```

命名：`gf_<类别>_<对象>_<状态>_<方向>_v001.png`，全小写英文；同 ID 版本递增。每个资源包带 `asset_id, version, files, canvas_px, pivot, display_size, animation_events, color_space, license_source, generator_or_author, limitations`。源文件过大时先定 Git LFS 或私有存储策略，交付可访问索引，不将不可访问的外链标成已交付。

## 批次与验收流程

1. Codex 为批次提交一页 brief：用途、对象、风格、尺寸、锚点、状态、验收；Claude 先确认能导入。
2. 先做 1 套 Pip + 3 武器 + 3 敌人 + 工坊的代表稿，在同一主画面缩小检查。负责人选择方向后冻结，不让每个素材自由改变画风。
3. 若用图像生成，Codex 留存 prompt、工具/日期、参考图来源、原始输出与选稿。生成图须人工检查轮廓、部件数量、透明边缘和一致性；概念图不直接等于可用动画或可商用授权证明。
4. Codex 清理/分层/导出并填写 manifest；Claude 导入，用实际场景录屏返回，不能只看单张大图。
5. Codex 验视觉，Claude 验锚点/命中/性能，负责人确认关键资源。只有通过后改为 ACCEPTED；退回写明可复现问题。

| 检查 | 通过标准 |
|---|---|
| 识别 | 三形态、三敌人黑色剪影也能区分；实际显示尺寸下可辨；无需读长文字 |
| 技术 | 无白边、切边、跳 pivot、漏层、缺帧；武器挂点不漂移；资源缺失有明确报错 |
| 机制 | 看见的范围与真实命中一致；护盾/护甲/HP 不混淆；新武器生效时点和录像吻合 |
| 可用性 | 静音、Reduce Effects、色觉差异下保留形状/图标/数值提示；不依赖闪光读懂结果 |
| 权利 | 每份第三方图/音频/字体/参考来源可追溯；许可证允许拟定发行方式；未核实不进发布包 |
| 实机 | 目标 iPhone 上通过性能预算；UI 无截断、安全区遮挡；缩放没有破坏轮廓 |

音效库采购、专业骨骼绑定或音频外包若需要人工服务，Codex 给 brief 与预算，负责人安排；不能将这些工序默认为模型已经完成。

## 商店视觉

A4 在 RC 画面稳定后制作：图标 2 个方向选 1 个定稿；6 张截图依次展示“锻造改变攻击 → 三形态取舍 → 针对敌人改锻 → 符文效果 → Boss → 工坊成长”。覆盖到实际发布的功能，未开放的 P1 不出现。所有英文文案登记 strings.md，截图尺寸和图标导出方式在提交当天按 Apple 当前要求核对。

商店截图必须基于实际运行画面；可以做说明排版，不能以 AI 概念图代替实际玩法。若做预览视频，画面素材使用真实录屏。依据 [Apple 元数据与截图要求](https://developer.apple.com/app-store/review/guidelines/#accurate-metadata)，核对日期 2026-10-11。制作和发布步骤见 [上线手册](../release/app-store.md)。
