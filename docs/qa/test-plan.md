# 从逻辑到真机的测试计划

Claude 编写并执行可自动化的测试；负责人/指定测试员实际操作设备和主持真人测试；Codex 复核体验、规则与美术。**本文规定怎么测，不记录通过结果。** 每次执行复制 [记录模板](test-run-template.md)。

## 三类证据不能互相替代

| 层级 | 要证明什么 | 证据 |
|---|---|---|
| 自动逻辑 / 配置 | 规则、边界、状态机、存档事务正确 | 实际命令、退出码、日志、commit、固定 seed/config |
| 客户端真机 | 安装、触摸、画面、音频、系统中断、性能、平台能力可用 | 可安装 build 与哈希/编号、机型、OS、操作步骤、录像/截图、仪器输出 |
| 真人玩法 / 留存 | 能看懂、会自主改锻、愿意玩和回来 | 独立参与者、协议、逐人/分组数据、有效分母、观察窗、提示曝光与退出原因 |

没有设备的测试记 `NOT RUN/BLOCKED`，模拟器测过的写 SIMULATOR。没有真人的场景不能填 USER PASS。当前 Python 8 条经济测试不等于 46 条客户端 AC 已通过。

## 每次提交的必要检查

```bash
python tools/check_prd.py
python -m unittest discover -s tools -p "test_*.py"
```

Claude 在 BOOT-01 增加实际客户端构建/逻辑测试命令至工程 README 和 CI。数值变更重算快照；素材变更检查导入/可读性/性能；支付或存档变更跑对应完整事务回归。不能只加镜像实现的测试，也不因改一行文档重跑整套真人实验。

## 真机设备与性能

M0 只需一台团队现有 iPhone；BOOT-01 填具体型号和 OS。M1 形成 A13 基线；M6 必须覆盖下列矩阵，设备缺失是对应发布覆盖项未完成。

| 设备档 | 目的 | 发布前覆盖 |
|---|---|---|
| 最低支持档 A12（XR/XS），可获得的最低目标 OS | 最差性能、内存、兼容性 | 完整核心回归、降低特效、冷启动与长时间运行 |
| A13（iPhone 11） | PRD 性能验收基准 | AC-37 的 40 敌人 + 300 粒子压力；同一配置 3 次 60 秒 |
| 较新 iPhone / 当前正式 iOS | 当前系统、刘海/灵动岛、安全区、平台 SDK | 新装/升级、购买/广告、触摸及后台恢复 |
| 实际支持范围内最小和最大布局 | UI、单手与文字 | 真机点击，按钮/文字/预览不被遮挡；模拟器截图只能辅助 |
| 两台支持 iCloud 的真机 | 云存档/权益 | 同账号冲突、恢复、断网同步 |

设备可一机覆盖多项，但不能用一台新机宣称 A12 性能通过。若旧设备/最低 OS 无法取得，记录覆盖缺口并先调整支持声明与 PRD 后再发布，不能悄悄忽略。构建 SDK 版本与最低运行 OS 是两件事。

测量使用 Release 配置，记录构建、配置、场景、设备/OS、环境温度、屏幕亮度、是否充电、网络、仪器方式。预热后采样；记录平均/尾部帧耗时、峰值内存与 thermal state。测耗电时不接充电器，并记录电池健康状况；仪器连接造成偏差时单独注明。

沿用 PRD 10.10 和 AC-37：A13 压力场景平均 ≥58 fps 且无单帧 >50 ms、内存 ≤350 MB；A12 ≥30 fps；逻辑帧 ≤2 ms、触控反馈 ≤50 ms；冷启动到标题 ≤3 s/可操作 ≤5 s；首下包 ≤150 MB；iPhone 12 连玩 30 分钟耗电 ≤10% 且不降频。冷启动测 5 次逐次记录，触控延迟用高帧率录像或仪器验证，包体用实际分发尺寸。它们是待实测的项目目标，未达则修复或先修改范围/预算再重新验收。

## 真人验证与数据判定

M0 按第 0 章，内部 3 人排障与外测 12 人分开。测试时锁定 commit/build/config/seed/资源版本，不边测边改；有技术中断保留日志，坏成绩和提前退出不能删掉。主持人只用规定语言，迁移前不问引导答案的问题。

报告保留每位匿名参与者的：首分钟耗时、是否真实多目标命中、学习完成、两题各自尝试/输赢/提示曝光、事后理由、是否自主再试、退出/中断原因。按照第 0 章计算，不以“大家反馈不错”替代四项闸门。

M3 起按 PRD 11 的安装 cohort 与窗口汇总，报告分子、分母、成熟时间、置信区间和内容耗尽率。参与者录屏和联系方式放受控位置，公开 GitHub 只放去标识化表和证据索引；录屏先取得参与者同意。负责人管理招募资料和原始证据访问。

## 缺陷分级与放行

| 严重度 | 例子 | 放行规则 |
|---|---|---|
| S0 | 存档丢失、重复扣费/发货、公开凭据、无法启动 | 立即停止测试扩散或发布，修复并回归受影响路径 |
| S1 | 必经流程卡死、无提示实验泄漏、关键战斗规则错误、必测设备不可运行 | 阻塞对应阶段/发布 |
| S2 | 可绕过的 UI/反馈问题、非关键表现错误 | 明确影响与修复任务；负责人接受后才可带入下一阶段 |
| S3 | 不影响理解的小装饰问题 | 记入后续批次，不挤占 M0 |

发布候选版要求适用关键用例全部通过、S0/S1 为零，S2 有明确接受记录，未覆盖设备/场景可见。任何代码、SDK、关键配置或资产替换后，重新执行受影响测试并升级候选版标识；不能复用旧 build 的全绿截图。
