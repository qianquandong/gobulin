# 测试执行记录模板

复制成 `docs/qa/runs/<日期>-<阶段>-<run_id>.md` 后填写。目录由首次执行者创建。空模板不算测试证据，未运行默认 `NOT RUN`。

## 执行身份

| 字段 | 实际值 |
|---|---|
| run_id / 日期时间及时区 | 待填 |
| 执行人 / 复核人 | 待填 |
| 阶段 / 任务 ID / 测试类型 | 待填：逻辑、模拟器、真机、真人 |
| Git commit / 分支 / 工作区是否有改动 | 待填 |
| App version / build number / 包哈希 | 待填或 N/A（说明原因） |
| config_version / seed / 资源版本 | 待填 |
| 设备型号 / OS / 引擎 / Xcode / SDK | 待填 |
| 安装方式 / 新装或升级 / 存档 fixture | 待填 |
| 网络 / 权限 / 账号类型 | 待填；不填密码、Apple ID 或票据 |
| 日志/录像的受控位置或去标识化附件 | 待填 |

## 用例结果

| 用例 ID | 前置与输入 | 实际步骤 / 命令 | 期望 | 实际观测 | 结果 | 证据 / 缺陷 |
|---|---|---|---|---|---|---|
| 待填 | 待填 | 待填 | 待填 | 未运行 | NOT RUN | 待填 |

允许结果：`PASS / FAIL / BLOCKED / NOT RUN / N/A`。N/A 必须有阶段/范围理由；PASS 必须有实际观测和证据。失败用例附最短复现、发生频率、受影响版本、严重度和修复 PR。

## M0 真人记录附表

每位受试者一行，使用随机编号，不公开姓名或联系方式。

| participant_id | 首分钟秒数/达标 | 学习完成 | 题序 | 题1尝试/成功/提示 | 题2尝试/成功/提示 | 解释效果与代价 | 自主再试 | 退出/中断 |
|---|---|---|---|---|---|---|---|---|
| 待填 | 未运行 | 未运行 | 待填 | 未运行 | 未运行 | 未运行 | 未运行 | 待填 |

另附两题配置、不同答案配方及种子 1–10 的逐次结果；补测或技术替补写明理由并保留原记录。四项指标逐项列出分子/分母与第 0 章阈值，不将诊断性补充结果计入主指标成功数。

## 本轮结论

- 通过 / 失败 / 阻塞 / 未运行的用例数量：待填。
- 关键缺陷与已修复后的回归证据：待填。
- 尚未覆盖的设备、权限、场景和数据窗口：待填。
- 是否满足阶段闸门及依据：未评估。
- 下一步任务、责任人、解除阻塞条件：待填。
- 对具体 build/config 的放行人和时间：未放行。

测试报告必须能由另一人用相同输入复现；发布报告须对应实际提交的 RC。公开报告先检查是否包含个人信息、账号资料、设备标识或凭据。
